# 设计主题

按[维护约定](https://github.com/StuHelper/stuhelper-next/blob/develop/docs/authoring.md)填写实际内容，删除不适用章节。规则、方案、进度与结果分别表达，确认依据沿用已有授权和实际讨论。

## 目标与范围

说明谁在什么场景遇到问题、期望结果、覆盖范围与非目标；链接行为规格和实际条件。

## 核心概念

解释概念的职责与关联，用贯穿例子消除歧义；精确规则引用规格。

## 系统边界与核心方案

说明系统边界、模块与数据所有权、主要交互和核心机制，按需要配图。

## 业务流程与失败恢复

描述参与者动作、资源生命周期和失败点；结果未知时写清查询与恢复责任。

## 设计取舍与待确认事项

记录实际候选的收益与代价、仍需证据的问题，以及触发后续演进的条件。

## 关联与确认依据

链接相关规格、开发记录与决策，写实际确认依据；未决定的部分明确保留。
